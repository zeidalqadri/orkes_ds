What's missing is the **auto-discovery loop** — arbos's skills are frozen the moment a human stops curating them. This pipeline describes how to close that loop.

## Concrete Adopt/Adapt Proposals

### 1. Skill discovery loop (arbos-) — ADOPT
Wire the existing experts into a `skill-discover` workflow that runs weekly:
- `researcher` → scan GitHub trending, Claude Code plugins, MCP servers for new patterns
- `analyst` → filter: is this a new workflow or just noise?
- `Explore` → read docs/README, return intent + interface
- `reviewer` → score against arbos's quality bar (no slop, concrete, actionable)
- `write-a-skill` → generate SKILL.md + register if score passes
- `publisher` → commit to `~/.claude/skills/`, notify operator

**Effort**: 1-2 hours. The agents exist. The workflow script (parallel → filter → sequential pipeline) is the only new code.

### 2. Score-gate before investment (arbos- + sec-) — ADAPT
The tweet's "score validates against objective criteria — if it fails, it dies here" is the key efficiency pattern. arbos currently runs skills on request without pre-validation. Add a scoring gate to `skill-improver`: before investing tokens in skill generation, validate the source against 3 objective criteria (novel pattern? actionable? minimal deps?). Kill early, invest late.

### 3. Install-ready reviewer standard (arbos- + sec-) — ADOPT
The tweet's reviewer criterion — "would an experienced engineer install this without editing it?" — is a better bar than arbos's current "syntax valid, passes tests." Add this as a reviewer dimension in `experts.json` for the reviewer expert. A skill that needs editing to work is a draft, not a deliverable.

### 4. Docs-first reader (arbos-) — ADOPT
"Reader builds context from docs first, never from source code." This is a prompt-engineering change for the Explore/researcher agents: instruct them to read README/DESIGN.md/CLAUDE.md before source files. Reduces token spend and improves understanding of intent vs implementation.

### 5. Compound effect tracking (arbos-) — ADAPT
"Stronger skills lead to better discoveries." Track skill provenance: when a skill was generated from a discovery, and that skill later enabled a better discovery, log the chain. This makes the compounding visible and justifies the loop's token cost to the operator.

## What NOT to adopt

- **Auto-merge**: The tweet explicitly says "nothing merges automatically" — arbos already follows this (operator approves via Telegram).
- **8-agent count**: arbos's expert fleet is the right size. Don't add agents to match the tweet's architecture — use existing ones in a new workflow.
- **GitHub-only scope**: arbos should scan broader sources — Claude Code plugins, MCP servers, Anthropic cookbooks, not just GitHub repos.
