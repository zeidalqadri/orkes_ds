## Verdict: MEDIUM — sec- adopt; arbos- note-only

## Relevance

### sec- (HIGH)
sec- runs 4 portal scrapers (ePerolehan, SmartGEP, ForSAH, eTimad) that hit government procurement sites. IP bans are a real failure mode — SmartGEP auth tokens already go stale from rate limiting (token carousel issues observed Jul 29). mubeng is a drop-in Go binary that:
- Verifies proxy availability before routing
- Rotates IP per request from a configured pool
- Supports HTTP, SOCKS4/5, and Amazon API Gateway proxy protocols
- Zero external dependencies — single binary

### arbos- (LOW)
arbos- bots call LLM APIs (OpenRouter, DeepSeek, Claude), not target websites. No scraping. No IP ban risk. The only marginal value is if arbos- ever front-ends a web-facing service that needs request distribution (not current architecture).

## Why

sec- scrapers currently use single-IP requests with timed delays (1.5s between requests) to avoid bans. This works until it doesn't — ePerolehan's JSF/AJAX endpoints are already volatile. A proxy rotation layer would let sec- increase scrape throughput without increasing ban risk. mubeng specifically fits because:
1. Go binary — compatible with the existing sec- pipeline (no Python dependency clash, no npm)
2. Verifies proxies before use — no blind routing to dead proxies
3. Amazon API Gateway support — useful if sec- ever routes through AWS for Malaysian government portals
4. One-command setup: `mubeng -f proxies.txt -a 127.0.0.1:8080`

## Concrete Proposals

### ADOPT (sec-): Proxy rotation layer for portal scrapers
- Install mubeng binary system-wide (`go install github.com/kitabisa/mubeng/cmd/mubeng@latest` or download prebuilt)
- Configure with a proxy pool (start with 5-10 HTTP proxies)
- Route ePerolehan + ForSAH scrapers through mubeng on localhost
- Measure: ban frequency before/after, throughput delta
- Risk: proxy quality matters — dead proxies waste requests. mubeng's built-in verification mitigates this.
- Effort: ~2h (install, configure, wire into scraper fetch path, test on one portal)

### ADAPT (sec-): Proxy health as an Albert metric
- If mubeng is adopted, add proxy pool health to Albert's infra watch (active/total proxies, failure rate)
- Fits Albert's L1 "detect + suggest" upgrade path

### SKIP (arbos-): No scraping use case
- arbos- bots are pure LLM API consumers. No IP ban risk from web scraping.
- If arbos- ever adds web-facing API endpoints behind a load balancer, revisit.

### EVALUATE: Alternative to consider
- `proxychains` is already available on most Linux systems and works with Python subprocess. If mubeng adds operational complexity, proxychains is the simpler fallback.
- mubeng's advantage is built-in proxy verification + rotation logic that proxychains lacks.
