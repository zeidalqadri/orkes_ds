## Why

- `/home/the_bomb/orkes/packages/orkes_core/orkes_core/health_check.py` already checks memory pressure, DB/WAL size, disk space, tokens, and alert delivery; the missing layer is host security configuration and its changes over time.
- The post describes an unverified third-party Bash script. Running it with elevated privileges or allowing it to change SSH/firewall settings would add operational risk without proving coverage for this host.

## Adopt / adapt

1. **Add a read-only `host_posture` probe to the existing health path.** Emit one compact structured result for SSH password/root-login state, firewall status, sudo/audit log availability, disk free, RAM, swap, and service-manager reachability. Mark unavailable checks as `unknown`; never require privilege escalation in the scheduler.
2. **Baseline and diff, rather than repeatedly dump configuration.** Store a sanitized fingerprint and alert only on a posture downgrade or a sustained resource threshold breach. Route the result to the existing Comcen/Telegram health digest with the affected check and recommended manual command.
3. **Keep remediation deterministic and approval-gated.** The probe may recommend a firewall, SSH, log-rotation, or swap action, but it must not edit access-control settings, reload SSH, change firewall rules, or invoke `sudo` unattended.
4. **Pilot on the SEC host first.** Add fixture tests for healthy, unavailable, and degraded signals; measure false positives and operator usefulness for one week before exposing it to every arbos loop.

## Do not adopt

- Do not install or schedule `vps-audit` directly.
- Do not make generic host audit findings an LLM diagnosis/action path. The checks and thresholds should remain local, deterministic, and cheap.
