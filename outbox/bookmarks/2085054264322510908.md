## Verdict: MEDIUM — skill definition already installed but broken; fix enables a token-efficiency lever we're not using

### Relevance: arbos- MEDIUM, sec- LOW

**Why arbos- MEDIUM**:

book-to-skill converts technical books (PDF, EPUB, DOCX, HTML, Markdown, RTF, MOBI) into structured Claude Code skills: SKILL.md + chapters/ + glossary + patterns + cheatsheet. One extraction (~$1 per book, 0.96 for 371 pages), then 24-51x fewer tokens per session (5K vs 200K loaded). The output is a reusable skill — named frameworks, decision rules, techniques, anti-patterns — not raw text the agent re-parses every turn.

**Current state on this machine**: We have the SKILL.md (634 lines, 30KB, installed 2026-07-07) and the extract.py wrapper (27 lines). The wrapper imports `from book_to_skill.cli import main` — but the `book_to_skill` Python package is NOT installed. No pip package, no git clone, no `book_to_skill/__init__.py` anywhere on the filesystem. The skill is defined but inoperable.

**Why this matters for arbos**:

1. **Token efficiency at scale**: The arbos fleet runs ~18 agent steps/day across orkes_ds2, orkes, orkes_sec, Buzz2, OrkesBayu, tronzz. Every step re-loads CLI reference docs, schema docs, and domain knowledge. If even 3 key reference documents (HARGA_CLI_REFERENCE.md, harga_v8 DB schema, pricing patterns) were compiled into skills via this pattern, we'd cut per-step context consumption by 10-30K tokens.

2. **Compile-time over query-time**: This is the SAME pattern we adopted via skill-discover and skill-improver (P2/P3 gates, "kill early, invest late"). book-to-skill applies this to domain documents — extract structure once, load on demand. Our existing `context/HARGA_CLI_REFERENCE.md` is loaded as raw markdown every step. A skill-ified version would be a 5K token structured toolkit.

3. **Shared learnings as a skill target**: shared_learnings.md is 192 lines of flat facts. book-to-skill's extraction approach (layers, frameworks, anti-patterns) is the same layering pattern we just proposed from the TencentDB-Agent-Memory triage. This is convergent evidence that the pattern is right.

**Why NOT higher**:

1. **Already installed — just broken**: The skill definition exists. Fixing it is `pip install book-to-skill` or `git clone && pip install -e`. Low effort, not a new capability.
2. **No arbos-specific docs warrant conversion today**: HARGA_CLI_REFERENCE.md and shared_learnings.md could benefit from skill-ification, but they change frequently (new learnings, evolving schema). book-to-skill targets stable reference books — not living project docs. Converting a moving target is premature optimization.
3. **Not a new insight**: The compile-time vs. query-time pattern is already internalized in our pipeline (skill-discover, skill-improver guard gates).

**Why sec- LOW**:

sec-agent works on infrastructure, security, webdav-intel, and tender pipelines. Its context comes from logs, pm2 state, and scrape outputs — not from books. None of the sec- knowledge sources (scraper patterns, auth flow sequences, API contracts) are book-length documents that benefit from structured extraction.
