sec- owns user-facing Harga web surfaces where small omissions in navigation, forms, loading/error states, tables, uploads, and approval/assignment flows directly affect bid work. ## Concrete adopt/adapt proposals

1. **Create a local `ui-release-checklist.md` from applicable items only.** Cover navigation, cards/tables, input validation, loading/empty/error states, destructive actions, uploads, responsive layouts, and keyboard focus. Keep it in the Harga vX/v8 documentation, versioned with the code; do not depend on an external SaaS or Figma plugin at runtime.
2. **Add a generative-maintenance prompt gate.** When an agent changes a sec- web screen, require its PR/hand-off to state which local checklist rows were checked, what is intentionally out of scope, and the exact route/API states exercised. This makes model-produced UI reviewable without turning aesthetic judgement into an autonomous release decision.
3. **Use it on the next bounded UI repair.** Apply the rubric to a tender-detail or assignment/approval screen with known API failures. Verify normal, empty, loading, 4xx/5xx, and retry states manually plus existing automated checks. Promote the rubric only if it exposes an omission not caught by present review.
4. **Keep arbos- adaptation narrow.** Apply only to Comcen/Telegram-linked web dashboards: dense data layout, status colour meaning, stale-data timestamp, keyboard/reload behavior, and failure-state visibility. Do not expand it into a bot workflow or a new agent tool.
