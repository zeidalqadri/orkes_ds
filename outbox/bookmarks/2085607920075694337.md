## Why it matters

### arbos- — MEDIUM

Arbos agents are intentionally local and privileged: they inspect PM2, local SQLite files, private repositories, runbooks, and machine health. Moving that loop to a Worker workspace would remove the very host access used for diagnosis and remediation. It is useful only as a remote, disposable workbench for public-source experiments, generated artifact checks, and repeatable low-risk skill validation.

### sec- — HIGH

`/home/the_bomb/orkes_sec/wrangler.jsonc` already runs the `harga-work` Worker with `nodejs_compat`; its current worker is a trusted edge proxy. Computer-style workspaces can add isolated execution for narrow, non-secret workloads without coupling that proxy to the host. The strongest opportunity is reproducible packaging and validation around public code or sanitized fixture data, while credentialed scraping, browser/permauth, tender databases, and PM2 operations remain local.

## Adopt / adapt

1. **Pilot a separate Worker, never the `harga-work` ingress Worker.** Create one non-production Durable Object namespace and one workspace per immutable job ID. No shared/global workspace, no production route, no access to Harga origin secrets.
2. **Start with one bounded sec- task:** build/test a public or sanitized extractor fixture, return only a signed result manifest and archive, then compare elapsed time, failure rate, and spend against the existing local route for 10 runs. No live portal login, WebDAV, source database, or tender document enters the pilot.
3. **Use arbos- only for artifact verification.** Permit generated runbooks/CLI help/output fixtures to be linted or smoke-tested in the remote workspace; retain host diagnosis, code edits, package installs, git push, process control, and secret-bearing work in the current local loop.
4. **Install an execution policy before an agent tool.** Allowlisted commands, fixed CPU/wall-time/output limits, read-only checked-out inputs, no network by default, no credentials in files/environment, audit record `{job_id, source_ref, command, hash, exit_code}`, and explicit human approval for network or container escalation.
5. **Set promotion gates.** Pin the package version and a compatibility date; record Worker/DO/R2/container/AI spend separately; promote only if the 10-run pilot is at least as reliable as local execution, materially reduces host memory contention, and has a tested delete/export path. Otherwise remove the pilot namespace.

## Do not adopt

- Do not replace the pm2/Claude Code/OpenCode maintenance loops, SmartGEP authentication, local SQLite workflows, or local browser automation.
- Do not hand a model unrestricted `exec`, git credentials, R2 access, or a persistent production workspace.
- Do not route on “free model” claims. Model availability, privacy, rate limits, and billing are separate from the workspace runtime and require their own provider-approved evaluation.
