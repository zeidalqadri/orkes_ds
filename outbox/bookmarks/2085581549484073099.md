## Verdict: MEDIUM — useful orchestration patterns; do not adopt the product on its claims

### Relevance: arbos- MEDIUM | sec- LOW

**arbos- — MEDIUM**

The useful part is a policy layer that selects a known-capable executor, controls prompt shape, and bounds validation. ArbOS already has the raw pieces: provider routing, an expert fleet, GOAP plans, `STATE.md`, and a runaway watchdog. Recent DeepSeek model-not-found failures show the missing operational detail: routing must be capability-verified and failure-aware, not a static “best model for task” claim.

The post's vendor matrix, autonomous goal refinement, and “just install” framing are marketing claims, not evidence. A new top-level orchestrator would duplicate the pm2 loop, add another state store, and increase failure surface.

**sec- — LOW**

sec- work is primarily authenticated portal scraping, deterministic pipeline execution, and guarded remediation. Model routing can help classify logs, summarize documents, or triage a failed run, but it must not choose credential flows, browser actions, SQL writes, or restarts. The cited multi-vendor stack does not solve session expiry, portal-contract drift, or process recovery.

### Concrete adopt/adapt proposals

1. **ADOPT: capability-verified route table in ArbOS.** Keep model/backend choice in one versioned policy: task class, allowed models, context/token limits, retry fallback, and a health probe. A failed `model_not_found`, auth failure, or quota failure immediately marks that route unavailable for the current run and selects an approved fallback. Do not infer support from a catalog entry.

2. **ADAPT: verification budgets by risk.** Add a small per-goal budget to the plan: read/report = one targeted verification; code change = targeted test plus syntax/import check; production action = deterministic pre/post health checks. Stop when acceptance criteria are met; retain the existing watchdog for loops with no state movement. Do not use an LLM to suppress checks on credentials, payments, deployments, database mutation, or scraper auth.

3. **ADAPT: bounded task-normalization contract.** Before dispatching a complex goal, the conductor writes outcome, constraints, acceptance criteria, and a maximum work scope. It may clarify an ambiguous task only from local context; it must not silently broaden the operator's request or rewrite the goal into a different project.

4. **SKIP: install Oh-My-Hermes or its vendor swarm.** There is no demonstrated compatibility, security model, cost control, or advantage over the existing pm2 + `STATE.md` loop. Evaluate only if a reproducible local pilot proves a capability-verified route table reduces failed steps without adding an external control plane.

## Guardrails

- Keep provider credentials, routing configuration, browser sessions, and remediation permissions out of any generated prompt or external orchestrator state.
- Executor routing remains advisory for generative work; deterministic code owns state-changing operations.
- Measure pilot value with failed-step rate, fallback recovery time, repeated-verification count, and token cost per completed goal.
