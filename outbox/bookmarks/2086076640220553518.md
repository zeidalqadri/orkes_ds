# Bookmark triage — TREK

- Source: @tom_doerr, 2026-08-08 — https://github.com/mauriceboe/TREK
- Verdict: **MEDIUM**
- arbos- relevance: **LOW**
- sec- relevance: **MEDIUM**

## Why

TREK is a self-hosted travel-planning product, not an agent, scraper, pricing, or procurement system. Its collaboration, maps, packing, journal, and PWA features do not transfer to arbos- or sec- operations.

The reusable engineering signal is its operational packaging: a dependency-minimised Docker image, read-only runtime with dropped Linux capabilities, explicit health check, persistent data/uploads separation, encryption-key rotation support, structured environment controls, and a versioned plugin SDK with manifest validation, local dev harness, pack/preflight gates, checksum pinning, and optional artifact signatures.

## Adopt / adapt

1. **sec- deployment hardening pilot** — adapt the Docker posture for one stateless sec API or worker: non-root runtime, read-only root filesystem, `no-new-privileges`, dropped capabilities, explicit writable mounts, and a `/health` probe. Keep SQLite and browser/OCR services out of the first pilot; record startup, memory, and recovery effects before wider use.
2. **versioned adapter release gate** — adapt the SDK lifecycle, not its JavaScript implementation: define a small manifest plus `validate` command for portal adapters and notification channels. Require declared capabilities, configuration schema, dependency version, smoke check, and rollback note before a SmartGEP/ePerolehan adapter release.
3. **extension preflight for generative changes** — add an offline preflight that checks syntax, secrets exclusion, required health endpoint, migration/rollback declaration, and fixture smoke test before an agent can package or restart a touched sec component. Preserve human approval for browser, credential, PM2, and external-message actions.
4. **Do not adopt the product or plugin runtime** — no travel features, PWA layer, real-time collaboration stack, or Node plugin host belongs in the existing Python/PM2 fleet without a concrete Harga use case.

## Decision

Use TREK as a reference for release hygiene and least-privilege self-hosting only. Create no dependency, service, or migration from this bookmark alone.
