## Concrete proposals

### 1. ADOPT: Pre-LLM document-to-markdown stage in sec-webdav-intel
- Drop anydoc binary into the webdav-intel scan loop BEFORE the existing LLM extraction call.
- Pipeline: `scan_dir → anydoc convert → markdown text → LLM extract line_items → price_memory.db`
- The markdown output is cleaner input for the LLM extraction prompt (no binary noise, structured text).
- Expected: "other" classification drops from 86% to <20% as actual content is parsed. Price memory yield per scanned file improves.
- Risk: Rust binary adds a build dependency. Mitigated if anydoc ships pre-built binaries (likely, given the Firecrawl pedigree).

### 2. ADAPT: Content-based file classifier to replace filename heuristics
- Current `classify_filename()` in WebDAVClient uses filename pattern matching — 66/466 matches.
- Replace with: `anydoc convert → grep first 500 chars for keywords (quotation/invoice/PO/BOQ/catalog) → classify`.
- Simple, deterministic, no LLM cost. Rust binary runs in <5ms/file — negligible overhead.

### 3. SKIP: Replacing existing OCR-server
- ocr-server (2.6GB RAM) handles image-based documents. anydoc targets binary formats (PDF/DOCX/PPTX), not images. These are complementary, not replacements.
- Do NOT touch ocr-server for this.

### 4. EVALUATE: anydoc as a shared system binary
- If anydoc proves useful for webdav-intel, install system-wide (`/usr/local/bin/anydoc`) and document in shared_learnings so sec-documents and any future doc-processing service can use it without re-evaluation.
- Gate: verify after 2 weeks of webdav-intel use that classification accuracy improved measurably.
