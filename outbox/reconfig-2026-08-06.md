## Findings

### 1. APPLIED — codex backend was broken; every step burned ~55s then fell back
- `ARBOS_BACKEND=codex` (orkes_ds2 + orkes_sec). codex 0.146.0 (responses wire API only;
  `wire_api="chat"` removed) fetches `GET {base_url}/models?client_version=...` when the
  models cache is stale. DeepSeek returns OpenAI shape `{"object":"list","data":[...]}`;
  codex 0.146 expects `{"models":[{slug,display_name,...}]}` → "missing field `models`" →
  rc=1 → 5 retries (~55s) → claude→proxy fallback.
- Fix: static catalog `~/.codex/models_catalog.json` (8 deepseek v4 entries cloned from the
  official models cache schema) + top-level `model_catalog_json` in `~/.codex/config.toml`.
  With a catalog present the refresh failure becomes non-fatal; verified end-to-end
  `codex exec -m deepseek-v4-flash` rc=0, clean turn, no metadata error.
- Backup: `~/.codex/config.toml.bak-reconfig-20260806`. No bot restart required.
- Side note: `models_cache.json` (18MB) fetched_at Aug 2 — this was the trigger; with the
  catalog, staleness no longer matters.

## Proposed reconfiguration (priority order)

1. **Ollama (~9GB)**: pin/quantize the enrich model (qwen3:8b per config, or smaller quant);
   unload on idle. Biggest single lever for swap relief. Needs sec-enrich validation.
2. **Close idle interactive opencode sessions** (~1.7GB) when not in use.
3. **ocr-server on-demand**: start per parse job, stop after; or lower to 1 worker.
4. **embed-server**: verify backlog — constant 4-5 cores; throttle batching or move to GPU box.
5. **Move heavy AI to glorycloud box**: ollama/ocr/embed/rag (SEC_RAG_MODE=thin already
   supports remote; extend same pattern).
6. **Disk**: add rotation for codex sqlite logs; prune reasoning_content.sqlite3;
   clear stale models_cache if desired.
7. **Orkes_Buzz2**: investigate 129-restart flap or restart clean with sane max_restarts.
8. **Mission alignment**: update this bot's `PROMPT.md` to reflect ops role (harga-cli is
   built); or explicitly re-scope to CLI work if that is still desired.
